Оптимизация по массе и габаритам. Лимит массы КТК — 33.5 т.
Результат (текст) 

      

    

  







  

    

      
Алгоритм распределения рулонов по КТК

      
    

    

      
Алгоритм решает задачу упаковки рулонов в контейнеры (КТК) с ограничениями по массе и диаметру. Цель — минимизировать число КТК и как можно плотнее подойти снизу к предельной грузоподъёмности 33.5 т на каждый КТК.


      
1. Входные данные

      
    
        
  • Список рулонов: для каждого известны масса (т) и внешний диаметр (мм).
    • 
        
  • Диаметр вычисляется по формуле: D = √(162196 · M / W + D_внут²), где M — масса в кг, W = 1340 мм — ширина, D_внут = 500 мм.
    • 
        
  • Тип КТК: 3 места или 4 места. У каждого места свои ограничения по массе и диаметру.
    • 
        
  • Максимальное число КТК (по умолчанию 108).
    • 
      


      
2. Схемы загрузки (паттерны)

      
Каждый тип КТК имеет оцифрованную схему — последовательность проходов, на каждом из которых заполняется определённое место:

      
    
        
  • 3-местный: "010" → "101" → "111"
          
      
            
    • Проход 1: центр (поз. 2), D ≤ 2200 мм.
      • 
            
    • Проход 2: рулон перекладывается из центра на левый край (поз. 1, D ≤ 1900), и кладётся новый в правый край (поз. 3, D ≤ 1900).
      • 
            
    • Проход 3: кладётся новый в центр (поз. 2), D ≤ 1600.
      • 
          
    
        
    • 
        
  • 4-местный: "1000" → "1001" → "1101" → "1111"
          
      
            
    • Проход 1: поз. 1 (D ≤ 1650, m ≤ 17 т).
      • 
            
    • Проход 2: поз. 4 (D ≤ 1650, m ≤ 17 т).
      • 
            
    • Проход 3: поз. 2 (D ≤ 1400, m ≤ 16 т).
      • 
            
    • Проход 4: поз. 3 (D ≤ 1200, m ≤ 16 т).
      • 
          
    
        
    • 
      


      
3. Подготовка

      
    
        
  1. Предфильтр. Рулоны, которые не проходят ни в один шаг ни по массе, ни по диаметру, выносятся в отдельный список «Неразместимые» и в расчёте не участвуют.
    2. 
        
  2. Сортировка. Остальные рулоны сортируются по убыванию массы (при равенстве — по убыванию диаметра). Так «неудобные» (тяжёлые и крупные) рулоны размещаются первыми, а лёгкие идут в «добивку».
    3. 
      


      
4. Основной цикл — «змейка» по КТК

      
Для каждого прохода схемы выполняется обход всех КТК. Направление обхода чередуется между проходами:

      
    
        
  • Проход 1 — слева направо (КТК 1 → 108).
    • 
        
  • Проход 2 — справа налево (КТК 108 → 1).
    • 
        
  • Проход 3 — снова слева направо, и т. д.
    • 
      

      
На каждом шаге для текущего КТК выполняется действие прохода:

      
    
        
  • PlaceNew — в указанное место кладётся самый тяжёлый из оставшихся рулонов, который проходит по массе и диаметру и не превышает суммарный лимит КТК (33.5 т).
    • 
        
  • MoveExisting — рулон перекладывается из одного места в другое (только для 3-местного). Если перекладывание невозможно (рулон не проходит по диаметру нового места), КТК закрывается — больше в него ничего не кладётся.
    • 
      

      
Если на текущем шаге ни один рулон не подошёл под свободное место — шаг просто пропускается, КТК переходит к следующему проходу.


      
5. Завершение

      
    
        
  • Алгоритм останавливается, когда закончились рулоны или закончились проходы схемы.
    • 
        
  • Рулоны, которые не удалось разместить из-за нехватки КТК/мест, попадают в список «Остаток».
    • 
        
  • Рулоны, физически не проходящие ни в одно место, — в список «Неразместимые».
    • 
      


      
6. Что показывает результат

      
    
        
  • КТК загружено — сколько контейнеров использовано.
    • 
        
  • Средняя загрузка — средняя масса на один КТК (чем ближе к 33.5 т, тем лучше).
    • 
        
  • Средний остаток — сколько в среднем «не добрано» до лимита.
    • 
        
  • Строки вида КТК#001 [9.00, 7.89, —, —]: 16.89/33.5 т — состав каждого КТК по позициям (— = пусто).
    • 
      


      
7. Особенности и ограничения

      
    
        
  • Алгоритм жадно-эвристический (не гарантирует математический оптимум), но за счёт «змейки» даёт равномерную загрузку КТК и хорошо работает на реальных партиях.
    • 
        
  • Если рулонов физически больше, чем могут вместить доступные КТК, часть уйдёт в «Остаток» — это не ошибка, а ограничение числа контейнеров.
    • 
        
  • Диаметры и массы мест можно менять в коде (объекты SlotSpec и PatternAction) — алгоритм не требует переписывания.
    • 
      


      

        Партия рулонов генерируется случайно при каждом запуске (seed берётся из текущего времени), поэтому два запуска подряд дают разные данные. Это сделано специально — чтобы можно было оценить устойчивость алгоритма на разных партиях.
